整体架构

当前代码已经从单一 MainWindow 逐步拆成 core、device、ui panels、ui modules、data、protocol 等层。MainWindow 负责装配和跨模块协调。

顶层分层

目录职责
afm_gui/core/扫描配置、扫描控制器、参数树、stage/lock-in/approach/spectroscopy 控制逻辑。
afm_gui/device/设备配置加载、DeviceManager、adapter registry、mock device、真实硬件 adapter、厂商驱动副本。
afm_gui/ui/panels/纯 UI 面板构建，尽量少放业务逻辑。
afm_gui/ui/modules/面板逻辑、信号连接、控制器封装、跨 UI 状态管理。
afm_gui/data/GSF 和 spectroscopy HDF5 数据读写。
afm_gui/config/设备定义、scan mode 定义、默认布局。
tests/核心逻辑和 GUI 模块 smoke tests。

扫描数据流

GUI / CLI
  -> ScanConfig + scan_modes.yaml
  -> DeviceManager + devices.yaml
  -> ParameterTree
  -> ScanController
  -> AdapterScannerDevice / MockScannerDevice
  -> LockinScanAcquisition
  -> line_data_ready
  -> images[scan_pass][channel][line, pixel]
  -> GUI display / GSF export / metadata JSON

真实扫描路径

GUI 扫描时使用 AdapterScannerDevice。开始扫描时，它向 Device Manager 请求 scan_scanner function 对应的 adapter。如果真实扫描器已连接，就在后台 worker 中逐点设置 X/Y 电压，并通过 acquisition callback 读取每个点的信号。如果没有真实扫描器连接，则回退到 mock scanning。

Lock-in acquisition 路由

LockinScanAcquisition 读取 Lock-in panel 中应用后的 Scan Routing 表，把内部 image channel signal_a 到 signal_d 映射到具体 lock-in 设备、通道和信号。

A -> zurich_HF2LI : ch1 : x
B -> zurich_HF2LI : ch1 : theta
C -> srs_sr830    : ch1 : r
D -> zurich_HF2LI : ch2 : frequency

如果某一路未连接或读取失败，该路填 0，扫描器运动不会因此被中断。这对硬件 bringup 比较友好。

UI 结构

GUI 使用 pyqtgraph DockArea。默认布局来自 afm_gui/config/layout1.json。Device Manager 启动时以浮动窗口打开；Lock-in Amplifier 和 Approach 可从 View 菜单打开；Spectroscopy 暂时隐藏。

硬件层结构

devices.yaml
  -> loader.py
  -> DeviceManager
  -> DeviceHandle
  -> registry.py
  -> adapter class
  -> package-local vendor driver

GUI 模块不直接 import 厂商驱动，而是通过 function assignment 和 adapter interface 使用设备。这让硬件替换尽量集中在 devices.yaml 和 adapter 层。

当前架构重点

  • MainWindow 已从“所有逻辑中心”转为装配器和跨模块协调器。
  • 扫描、stage、lock-in、approach、storage、metadata、layout、channel image 都有独立 module。
  • 真实硬件 I/O 尽量不阻塞 GUI 主线程。
  • metadata 是一等公民：扫描、显示、硬件、stage、lock-in、approach 状态都进入参数树。
