数据与元数据

当前普通图像扫描使用二维 image 数据模型和 Gwyddion Simple Field 导出。metadata JSON 记录复现实验所需的参数、显示状态和硬件状态。

内存数据模型

images[scan_pass][channel] -> 2D numpy array

scan_pass: trace / retrace
channel: signal_a / signal_b / signal_c / signal_d
shape: lines x pixels

GSF bundle 命名

如果在 GUI 中保存为 sample01.gsf，会生成：

sample01_signal_a_trace.gsf
sample01_signal_a_retrace.gsf
sample01_signal_b_trace.gsf
sample01_signal_b_retrace.gsf
sample01_metadata.json

每个 GSF 文件里会包含紧凑 metadata，并引用同目录下的 metadata JSON。

Auto Save

Auto Save 默认开启，默认目录为 ~/AFM_scans。暂停和完成时都会写一组带时间戳的文件：

afm_20260606_033000_pause_line0128_signal_a_trace.gsf
afm_20260606_033000_pause_line0128_metadata.json

afm_20260606_033500_finish_line0256_signal_a_trace.gsf
afm_20260606_033500_finish_line0256_metadata.json

Metadata 内容

分类内容
app应用名、metadata schema、创建时间、GUI/CLI source。
scan模式、方向、初始参数、当前/最终参数、几何、timing、channel、pass、单位。
displaychannel image 视图、flattening、color range、ROI 等显示状态。
runtime当前 line index、运行时参数修改记录。
storage手动保存、Auto Save 设置、autosave event 历史。
devicedevices.yaml 路径、设备快照、function assignment 快照。
stage当前 X/Y/Z 位置和 stage 状态。
lock-inchannel 设置、最新读数、Scan Routing A-D。
approachapproach 设置和最新 progress/state。

运行时可更新参数

这些参数扫描中修改后会从下一行生效，并写入 runtime update history：

  • linear
  • t_sample
  • t_settle
  • t_rest

width、height、pixels、lines、channels、scan mode 等结构参数属于下一次扫描设置。

内存估算

raw bytes = passes * channels * lines * pixels * 8
扫描规模raw image 内存
256 x 256, 4 channels, 2 passes约 4 MB
512 x 512, 4 channels, 2 passes约 16 MB
1024 x 1024, 4 channels, 2 passes约 64 MB
2048 x 2048, 4 channels, 2 passes约 256 MB
4096 x 4096, 4 channels, 2 passes约 1 GB

实际 GUI 运行时需要预留 raw data 的 3-6 倍给显示、临时数组、Qt/pyqtgraph 和导出操作。

Spectroscopy 数据

Spectroscopy MVP 使用独立 HDF5 bundle，扩展名为 .afmspm.h5，数据形状为：

spectra[scan_pass][channel] -> lines x pixels x spectrum_points
