# MIM 成像：FM 扫描 + 两台 GPIB SR830

MIM 模式沿用 FM-AFM 的 HF2 XY 控制、扫描几何、逐像素停留、正反向扫描、暂停和停止流程。
HF2 AUX1/2 控制 XY，AUX3/4 分别记录 Z PID 和 PLL Δf 输出电压。
新增 `sr830_I` 和 `sr830_Q`，分别读取两台外接 SR830 的 **X**，并非同一台仪器的 X/Y。
默认四幅图为 AUX3、AUX4、MIM I、MIM Q；需要时可以额外勾选 AUX1/2。

## 连接与启动

1. 在 Device Manager 中连接 HF2，并将 `Scan Scanner` 指向 `zurich_HF2LI`。
2. 配置并连接 `sr830_I`、`sr830_Q`。示例地址分别为 `GPIB0::8::INSTR`、`GPIB0::9::INSTR`，
   应改成仪器实际地址。同一 GPIB 总线上，两台仪器必须设置不同地址。
3. Function Assignments 中，`MIM I / SR830 X` 对应 `mim_i`，`MIM Q / SR830 X` 对应 `mim_q`。
   默认已指向上述两个设备；可以改成其他配置的 SR830，但不能映射到同一仪器或同一 GPIB 资源。
4. 两台 SR830 使用电压输入 A 或 A-B；在仪器上设置解调参考、相位、灵敏度、滤波斜率和时间常数。
   I/Q 的物理定义取决于外部接线和相位标定，程序不会自动旋转或重新标定 I/Q。
5. Scan Mode 选择 `MIM / FM + dual SR830 X`。左侧自动变为建议器，原 FM Monitor 停止并隐藏。
6. 设置扫描几何和时序，查看建议器，在两台 SR830 上确认实际设置，再启动扫描。

SR830 通信沿用项目现有的 QCoDeS / VISA 后端。电脑需要可用的 GPIB 控制器驱动与 VISA 库。
MIM 不会回退到模拟成像。设备断开、角色缺失、型号错误或地址冲突都会拒绝启动。
目前 MIM 实机采集从 GUI 启动；旧 CLI 的 `scan` 命令只支持模拟扫描，因此会拒绝 `--mode mim`。
默认 SR830 VISA 超时为 1 秒，可在连接配置的 `kwargs.timeout` 中修改，单位为秒。
旧配置缺少 `mim_i` / `mim_q` 时，需要加载包含这些角色的新设备配置。

## 每个像素怎样读取

每像素执行：移动到目标 XY → 等待 `Sample` → I 仪器 `OUTP? 1` → Q 仪器 `OUTP? 1`
→ HF2 AUX 批量读数 → 一次提交该像素 → 移动到下一像素。
仅要求已勾选的 SR830 通道连接。只连接一台时，取消另一通道的勾选即可；只勾 I 或只勾 Q 均可。两个通道都未勾选时，仅采集所选 HF2 AUX。

读取路径只查询选中的 X，不在每像素额外查询 Y、R、相位或频率，也不循环软件平均。
不重试失败查询、不将失败值填成 0、不缓存旧读数充当新像素、不对返回数字进行小数位截断。
XY 在 I/Q 读取期间保持不变，回扫数据反向排列后存入相同图像坐标。

两台仪器是**依次读取**。同一像素坐标不等于同一采样时刻；对于随时间变化的信号，
I/Q 仍可能有时间偏差。程序记录完整像素读取的平均/最大耗时，以及两个查询的主机时间中点间隔。
这些数值不能替代仪器时间戳。需要严格同时采样时，应另用共同硬件触发或同步采集链路。
目前没有以未经验证的缓冲区批量读数替代像素配对，因为当前 XY 是软件逐点移动，缺少共同触发。

每行后更新建议器中的实际耗时。这里“一整行”包含正扫、回扫、移动、Settle、暂停和 I/O，
不包含该行结束后的 Rest。速度设置不是硬实时周期承诺：实际速度取决于 HF2、GPIB、滤波和 Windows 调度。

## 时间常数建议

建议器默认跟随 Scan Parameters，也可以取消 `Follow Scan Parameters`，手动输入单程有效行时间和像素数。
手动输入的时间应只包含有效扫线，不含换向、Settle、Rest；若测量的是正反扫总时间，应先拆分。

设有效单程时间为 T、像素数为 N，平均像素间隔为 T/N。
当前实现是先移动后停留，因此跟随模式以 `min(T/N, Sample)` 作为稳定预算，
不会把移动耗时或 GPIB 查询耗时全部计为到达像素后的稳定时间。
手动模式采用 T/N 作为假设预算，需要自行确认该时间确实可以用于稳定。

滤波器按 6/12/18/24 dB/oct 对应 1/2/3/4 级 RC 模型估算阶跃响应，
可选择 95%、99% 或 99.9% 稳定目标。99% 对应约 4.605、6.638、8.406、10.045 倍 τ。
建议从 SR830 的离散时间常数中，选择满足稳定预算的最大值，在当前时间约束下尽量保留降噪能力。
如果连最短的 10 µs 都不满足，则明确提示增加像素停留时间。
该稳定百分比描述滤波响应，不代表信号绝对精度、总不确定度或空间分辨率保证。

例如：单程有效时间 2.56 s、256 点、24 dB/oct、99% 目标，手动模式的预算是 10 ms，
严格模型下推荐 300 µs；若跟随模式中 `Sample = 1 ms`，则推荐 30 µs。
较短的时间常数会提高带宽，也可能增加噪声；若信噪比不足，可增大 Sample，再选择更长的 τ。

建议器假设 Sync Filter 关闭。高动态储备和 Expand 可能抬高仪器允许的最小时间常数，
所以建议值需要在实际 SR830 上确认。扫描前在后台读取两台仪器的实际 τ、斜率、输入模式、
Sync、参考频率、谐波、灵敏度、储备、相位、X Offset/Expand，写入扫描报告。
若当前 Sample 小于按实际参数估算的 99% 稳定时间，会在 Command Log 提示；
不自动改写仪器。低频 Sync 开启时，提示估算还会增加一个检测周期，但这仍是近似评估。
运行中调整扫描 Sample / Linear 等参数仍在下一行应用，并重新检查稳定预算。

## 异常和数据保存

- 查询失败、非数值、NaN 或无穷值会停止扫描。该像素所有通道保持 NaN，已经完成的像素保留。
  这样不会只存 I 而丢 Q。通信失败发生在回扫时，已采部分也按图像 X 方向保存。
- 扫描前和每行结束读取两台仪器的 `LIAS?` 状态。检测到输入/滤波/输出过载或参考失锁则停止；
  行末检测异常时，无法定位具体受影响像素，因此将该整行置为 NaN，保留之前的行。
  检测到频段/时间常数自动变化也停止，避免继续用过期滤波参数解释数据。
  LIAS 是锁存状态，读取会清除；扫描前报错也可能来自之前的事件。
  应先核对仪器状态与原因，确认正常后重新开始。
- 扫描中的通用 Lock-in 面板读写被禁用，防止插入额外查询或改动解调参数。
  外部程序和前面板仍能改变仪器，不应在采集过程中修改它们。
- 停止/通信异常维持当前位置，不自动重置 SR830、HF2 输出或撤针。Z 闭环与 HF2 的保护仍由 LabOne/硬件负责。
  SR830 行末检查不是逐像素保护，也不检查 HF2 PLL/PID 状态；它不构成硬实时急停。
- 保存时同时生成每个通道/方向的 GSF、元数据 JSON 和 `*_raw.npz`。
  GSF 适合 Gwyddion，但格式采用 float32；NPZ 使用 float64，保留原始读数精度和 NaN。
  未经过显示平整的原始数据使用键名 `trace__sr830_I`、`retrace__sr830_Q` 等。

```python
import numpy as np
with np.load("sample_raw.npz") as raw:
    image_i = raw["trace__sr830_I"]
    image_q = raw["trace__sr830_Q"]
```

原始 X 的单位是 SR830 电压输入信号的 V，不是外部 ±10 V 模拟输出的电压，也不是已标定的阻抗/电容。
元数据包含实际连接、开始时的仪器设置、查询方式、耗时、失败原因和所在行。

## 协议依据与验证范围

协议与仪器参数核对自 [SRS SR830 官方操作手册](https://www.thinksrs.com/downloads/PDFs/Manuals/SR830m.pdf)：
§5-6（OFLT/OFSL）、§5-15（OUTP/SNAP）、§5-20/23（LIAS）、§3-21/25（滤波稳定时间）。
实现采用独立 RC 阶跃模型计算建议阈值；手册中的等待倍数为近似值。
自动化测试覆盖双机像素配对、回扫方向、断线、NaN、过载、停止、界面切换及 float64/GSF 导出。
尚未在真实 GPIB 控制器和两台 SR830 上测得吞吐率；应以首次小范围扫描显示的实际行耗时为准。
